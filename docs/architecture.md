# 架构与维护约定

## 更新路径

`Store.change(key, kind)` 明确区分 `messages`、`chat`、`members`、`unread`、`favorites`、`notification`。

- 正文、会话信息、成员变化：进入原生文档调度器，同一批变化合并；每次更新生成一次渲染结果。
- 已读、收藏、免打扰：更新列表及标签，不重渲染聊天正文。
- 草稿变化：更新草稿；回复目标变化时同时更新前缀。
- 代码风格变化：刷新可见文档，隐藏文档在再次可见时刷新。

文档更新顺序为：捕获各编辑器阅读位置和选区 → 生成投影 → 提交编辑 → 恢复选区和滚动。编辑失败时回滚前缀及位置映射，并释放快照。无文本变化时更新映射/高亮，不重复移动光标。

粘贴和拖入共享导入保护，防止异步准备附件期间的历史更新使插入位置失效。取消或失败时清理本次临时文件。关闭文档和切换账号会释放编辑器缓存。

## 发送约定

`submitDraft()` 只等待本地提交和界面更新，返回 `Submission`（消息 ID 与 `completion`）。Enter 命令使用此入口。后台队列完成时更新对应消息，不能再次清空当前草稿。

需要等待发送结果的内部调用使用 `sendMessage()` 或 `Submission.completion`；测试显式使用 `OutboxService.whenIdle()`。

- 每个账号/会话独立排队；文件与文本按原有顺序拆分。
- 最终提交前保存发件箱；用户新输入由草稿版本保护。
- 明确 API 拒绝为 `failed`；已提交但断线/超时为 `uncertain`，不能自动重发。
- 重连使旧代次任务失效；已经取得的成功回执仍结算到其原始仓库。
- 账号绑定串行执行，过期恢复结果不能覆盖当前账号。

## 数据兼容

消息段明确区分 `text`、`mention`、`image`、`face`、`file`。显示名称通过投影补充，原始文本保留。

v3 缓存兼容读取旧 v2 `text.at` / `text.file` 字段；普通文本中的 `@123` 不推断为真实提及。缓存格式升级只改变本地表示，OneBot 发送格式保持兼容。降级到旧插件前应保留 v3 缓存副本。

运行时设置定义与 `package.json` 的注册值由测试比对。新增设置必须同时更新注册及定义；设置页面从定义校验整批值后再写入。

## 验证与继续优化

- `npm run build`：类型检查与打包。
- `npm test`：协议、存储、纯渲染、缓存迁移、草稿和发送服务。
- `npm run test:extension`：隔离 VS Code + 模拟 NapCat，覆盖原生键盘、图片、文件、滚动、取消、重连和编辑失败。
- `npm run test:live -- <tuiqq-config>`：真实 NapCat 只读兼容检查。

后续可单独推进：从 Store 提取磁盘仓库、按消息块缓存渲染、拆分集成测试的场景初始化，以及继续收窄协议边界的 `any`。目前历史仍按会话整体投影，超大群的刷新性能需要用真实负载评估。
